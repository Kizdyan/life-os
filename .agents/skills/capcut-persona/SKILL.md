# CapCut Persona — provider-neutral editing skill

Use this skill in Claude Code or Codex when the task is to transform a user-authorized original video and a Persona `CapCutWorkPackage` into an editable CapCut-oriented handoff. A skill is a set of instructions; it does **not** itself connect to or control the CapCut application.

## Scope and prerequisites
- Read the existing `packages/core/src/capcut-work-package.ts`, `media-pipeline.ts`, `media-review.ts` and media QA modules first. Do not invent another incompatible edit schema.
- Only read expressly selected source assets. Never search unrelated folders; keep original paths and SHA hashes unchanged; never replace user-supplied pixels or alter actor identity.
- Confirm content ownership/licensing; distinguish private footage from public reference material. Reference clips are analysis input, not automatically licensed source clips.
- Default deliverable is an **editable handoff plan** plus SRT, generated by `node scripts/capcut-handoff.mjs <work-package.json> <asset-map.json> <new-output-folder>`.
- `asset-map.json` maps original `assetId` strings to *local paths*. Do not send those paths or bytes to external services.
- The handoff command is **not** a CapCut-native project generator and does not render MP4. An actual CapCut draft requires local editing or a separately approved/tested adapter.

## Workflow
1. **Intake**: record source filenames, content hashes, dimensions/fps/audio, rights/author approval, and desired format (normally vertical 9:16). Refuse to guess missing data.
2. **Reference breakdown**: record hook, timing, shots, framing, visual movement, captions, typography, color, transitions and audio. Cite original reference IDs. Reinterpret techniques, not exact creative assets or someone else's dialogue/music.
3. **Editing brief**: produce a valid existing `CapCutWorkPackage` (`clips`, `captions`, `overlays`, `audio`, `styleMemoryNotes`, `approvalRequired:true`). Protect original actor appearance, especially face, glasses, hands, clothing and skin texture.
4. **Read-only validation**: run `node scripts/capcut-handoff.mjs ...`; it checks asset mapping and timeline ranges and refuses to overwrite output folders. Keep originals untouched. For demonstration use `node scripts/capcut-handoff.mjs --self-test`.
5. **CapCut editing**: open the source clips in CapCut manually, or (only after a documented permissions/security review) use a local MCP adapter to create a *draft*. An unofficial `capcut-mcp-server` relies on third-party VectCutAPI; no official CapCut editing API is implied. Verify each tool's effect, save an editable project, and compare the draft with the handoff.
6. **Export and QA**: inspect the actual MP4 with `ffprobe` / `ffmpeg` and human review for subtitles, audio, 9:16 composition, color, integrity of actor appearance and rights. Do not fabricate measurements. A draft file or plan is not an exported video.
7. **Approval**: do not upload, comment, publish, send personal data, change accounts, spend money or automate activity on a social network without the appropriate separate approval.

## Approval gates
- **AUTO**: analyze authorised local footage and references, make local read-only report, prepare work-package and edit suggestions.
- **AUTO_REPORT**: render local previews only if the authorized toolchain is installed, with output under a new folder, no overwrite and independent QA.
- **APPROVAL**: third-party software installation, running an unaudited MCP server, transmitting personal footage externally, replacing originals, account posting, purchases and changing production state.

## Optional external MCP adapter (not installed by this skill)
Candidate: `https://github.com/Atx-Guy/capcut-mcp-server` + `https://github.com/sun-guannan/VectCutAPI`. Review dependencies, code, licenses, version pinning and CapCut terms before installation. Keep the HTTP backend bound to `127.0.0.1`, never the public internet. Verify CapCut version and Windows path handling using disposable footage; do not infer compatibility from a README. If this integration is absent, continue with the safe manual handoff.

## Output contract
Always provide: `source evidence`, `workPackage`, `handoff manifest`, `subtitle draft`, `technical QA`, `creative QA`, `remaining manual steps`, `publication blocked/unblocked`. Never claim a successful CapCut import or published Reel without observation.
