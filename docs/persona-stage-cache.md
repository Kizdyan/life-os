# Stage Cache Persona

Node Media Worker и Python используют одну локальную SQLite-базу в режиме WAL. При повторном запуске результат используется, если совпадают SHA-256 входных данных, операция, версия инструмента или модели и параметры этапа. Имя файла само по себе не влияет на ключ. Для рендера в ключ также входят монтажные настройки и содержимое использованных материалов: музыки, LUT, ASS, шрифтов и SFX там, где они применяются.

| Компонент | Что повторно используется |
| --- | --- |
| ProductionJob и Batch | FFprobe для проверки входа, музыкальная карта из закреплённого beat-synced-edit и итоговые рендеры Studio FFmpeg |
| Media Worker и семантический монтаж | Метаданные загруженных файлов, техническая диагностика дублей, измерения тишины и громкости, локальный Whisper, сборка таймлайна |
| Музыкальная студия | Анализ мастер-файла, рендер с фактическими настройками кадрирования, звука, цвета и титров, полное декодирование и технические измерения QA |
| Internet Learner | Метаданные, таймкоды смен сцен, шесть извлечённых кадров и отдельный структурированный ответ OpenRouter Vision для каждого кадра |
| Studio FFmpeg / StylePack | Проверенные MP4 и измерения пиков и громкости, привязанные к хешу MP4 |

OpenRouter Vision учитывает идентификатор модели, хеши кадров, промпт, схему ответа и, когда известен, хеш исходного видео. Если провайдер сменил модель под тем же именем, можно изменить `PERSONA_VISION_MODEL_REVISION`. Повторный импорт по интернет-ссылке заново проверяет содержимое через yt-dlp. Текстовые и аудиозапросы к модели, подготовка рабочих файлов, контактные листы QA и самостоятельные сценарии экспорта не используют кэш финального рендера.

При попадании в кэш итоговый MP4 записывается в текущий выходной каталог. Перед использованием проверяется SHA-256 сохранённых байтов. Метаданные, измерения и отчёты привязаны к фактическому выходному файлу. Ошибки обработки, таймауты и невалидные ответы не сохраняются. Если база недоступна, этап выполняется обычным способом. Два процесса, одновременно впервые запросившие один этап, могут выполнить его параллельно.

На Windows база по умолчанию находится в `%LOCALAPPDATA%\LifeOS\Persona\cache\stage.sqlite3`. Хранятся до 2048 записей и 512 МиБ данных, с лимитом 128 МиБ на запись. При нехватке места запись в кэш пропускается. Более крупные видео рендерятся обычным образом. Срок хранения локальных результатов составляет 30 дней, ответов Vision — 7 дней. База содержит локальные производственные данные, в том числе транскрипции, отдельные кадры и MP4.

- `PERSONA_STAGE_CACHE_DB` задаёт путь к базе для Node и Python.
- `PERSONA_STAGE_CACHE=0` отключает кэш.
- `PERSONA_STAGE_CACHE_LOG=1` включает строки `stage_cache MISS <этап>` и `stage_cache HIT <этап>` в stderr.
- Для кэширования в Node нужна сборка с `node:sqlite`, например штатный Node.js 22.13+ или 24. При отсутствии SQLite Node продолжает работу без кэша.
