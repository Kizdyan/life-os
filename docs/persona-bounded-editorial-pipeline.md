# Bounded editorial pipeline — AUD-03

Worker /carousel-editorial-pipeline uses existing token/auth, shared 5-external-calls/hour rate limit, explicit consent, maxCalls 2 or 4. Research -> independent reviewer -> at most one web-grounded revision -> reviewer. Provider-confirmed creator identity and distinct non-OpenAI critic are required. Missing provider/consent fails before calls; negative, stale, unchanged or unavailable review cannot produce an approved publication. Completed result (including prior attempt, report and last draft) is written to a unique local Worker output directory. UI imports final draft and exact verified text report without granting author approvals. Source review remains a separate human gate. Existing one-call paths unchanged.

Limits: this is one user-initiated editorial cycle, not a durable seven-item queue, scheduler or unattended background service. A crash before final result persistence can lose intermediate work; a paid request may already have occurred, so do not blindly repeat. Source-grounded revision prompt does not prove topic identity. No live model request made for development; tests inject fixtures, not real research. No new image generation, music catalog or platform sending. Actual provider identities, cost, model capabilities, full two-material production and local runtime require live acceptance. Main and external schedule untouched.

## Durable run reconciliation increment
A stable UUID v4 is stored in the browser before submission. The Worker claims an exclusive per-run directory, fsyncs the request claim and a numbered checkpoint before each paid call, and atomically renames the completed result. Same-ID POST with identical normalized request and authenticated GET return the persisted result without new provider calls; conflicting requests are refused. A pending browser run is queried read-only by default. Explicit same-ID retry is consented and cannot silently create a different run. If claim exists without a final result after restart, status is RECONCILIATION_REQUIRED, even if no checkpoint exists. The browser imports into the existing editorial store with stable content ID and verifies readback; prior imported drafts are not overwritten. Tests include filesystem journal, duplicate claims, call ordering and Worker restart with mocked providers.

Remaining: no auto-resume of ambiguous paid operations, no durable intermediate response checkpoint, no global durable hourly accounting across new IDs/restarts, no multi-device atomic queue admission, no seven-material autonomous batch. Recovery still depends on original outputRoot surviving restart; temporary directories must not be treated as permanent backups. User must reconcile interrupted provider charges before another independent run. UI and actual provider/Windows tests remain needed. No publication or paid call executed by development.
