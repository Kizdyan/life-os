# Cinematic carousel preview

In Persona → Editorial Desk, open «Почему самая страшная сцена часто тише всех». New drafts use eight different locally bundled cinematic backgrounds: stage, door handle, auditorium, spotlight, curtain, piano, black contour and final light. Six were newly generated for the v4 art revision; stage and curtain are retained. Older library files remain intact. «Кинофоны из библиотеки · все слайды» opts an existing draft into the new image sequence and resets design approval.

«Сгенерировать фон слайда · OpenAI» requests one text-free background through the authenticated local Media Worker. The worker reads `OPENAI_API_KEY` from its server environment (the existing launcher loads `.env.local`). The key never enters the browser bundle. This explicit action can incur provider charges. Missing credentials, unavailable Worker, timeout or provider failure returns `BLOCKED`, retains the current image and displays a warning. The local library and author archive remain separate choices; a blocked request is never presented as a newly generated image. No external API request is made on opening a draft or exporting it.

Provider configuration and automatic theme prompt: `config/carousel-backgrounds.json`. Bundled images and their provenance/fingerprints: `apps/web/public/carousel-backgrounds/v1/`. Generated images get a new immutable IndexedDB key and SHA-256; render verifies those bytes. Background references participate in the existing approval fingerprint. Old slides without background metadata retain their original hash and renderer.

## Native generation audit — 2026-11-22

The route is native Persona UI → local Worker `/carousel-background` → OpenAI Images API → base64 PNG response → browser decode → immutable IndexedDB asset → SHA-256-verified Canvas render. It does not invoke Codex imagegen. `codex-imagegen` provenance identifies separately imported external-tool images only.

The default model is now `gpt-image-2.5-sunburst`. Server-only `PERSONA_CAROUSEL_IMAGE_MODEL` can override it with an explicitly reviewed supported model, including dated Sunburst/Flare snapshots. The authenticated `/carousel-background/status` reports the effective model and credential presence only. Unknown, blank or retired model overrides return `IMAGE_MODEL_UNSUPPORTED` with `model: null` before any provider request; their raw value is never echoed. A configured key produces `NEEDS_CONSENT`, which does not prove provider access or billing readiness. Without a key it reports `BLOCKED` / `IMAGE_PROVIDER_NOT_CONFIGURED`. Each generation additionally requires `paidConsent: true`; the UI resets its checkbox after one request.

This updates the retired `gpt-image-1` default: OpenAI's [image endpoint reference](https://developers.openai.com/api/reference/resources/images/methods/generate) records its shutdown on October 23, 2026 and names Sunburst/Flare replacements. The adapter sends `n: 1`, `size: "1024x1536"`, `quality: "medium"`, and `output_format: "png"`, receiving `data[0].b64_json`. It omits the unsupported legacy `response_format` parameter. The requested provider image is 2:3; Canvas centers and crops it to the final 1080×1350 (4:5) artwork. Keep essential subjects within that crop.

Provider response reading is limited to 20 MiB, including chunked responses, and a 120-second timeout. PNG checks cover canonical base64, complete chunks/CRCs, requested dimensions, bounded decompression and scanline framing. The browser performs the final full image decode and pixel limits before accepting any IndexedDB write. Provider error bodies and exception details are never forwarded.

Verification uses a complete locally constructed PNG and an injected provider response, including an authenticated Worker contract test. These prove local routing, model selection, consent gating and response validation without making a paid API call. They do not prove real model access, billing, prompt quality or successful live generation. During this audit the checkout had no `.env.local` or process OpenAI key, and neither expected local Worker address was reachable: live generation is `BLOCKED`. Library images and earlier external-tool imports are not evidence of live Worker generation.

The unified port-3000 launcher now includes nested public JPG/JSON files in its in-memory frontend map. Previously its top-level-only copy omitted the background library and provenance JSON. The launcher regression test serves the actual v1 files and checks their exact bytes, MIME types and HEAD responses. Discovery skips symlinks/junctions; requests containing raw or encoded traversal are rejected before URL normalization. Importing the launcher for these tests does not start a Worker or open a browser; direct CLI startup is preserved.

Quiet Horror keeps the existing structured text model, now using only `headline` and `body` in its authored v4 composition. Cormorant Garamond 600/700 headlines and Inter 300 body text (44–48px / 1.6, opacity 0.9) load through `document.fonts.load`. Eight compositions use 100px margins, body columns up to 70% and Russian preposition-aware wrapping. No slide numbers, kickers, highlights or decorative lines appear inside the new PNGs. The slide-6 personal statement is included in both caption variants. «Применить тексты и фоны v4» updates an older saved draft and its standard caption variant, preserving custom captions; author approval remains required.

The bundled faces use renderer-only family aliases in `persona-editorial-fonts.css`. This prevents the existing app-wide Google Fonts import from replacing a face between the first render and export. Acceptance explicitly installs a competing global Cormorant face and verifies identical PNG hashes.

Canvas draws the photograph, a black-to-transparent gradient with maximum opacity 0.6, then the text. Preview and export use the same PNG. Images contain no generated lettering. `contact-sheet-quiet-horror-v4.png` replaces the v3 sheet in the explicitly mutable v4 preview release. Numbers 01–08 appear only below contact-sheet thumbnails; v1–v3 historical releases remain intact.

The workflow `persona-quiet-horror-review.yml` with `cinematic=true` exports the review-only prerelease `carousels-v4-cinematic-preview` from the selected branch, without requiring a merge. Existing tags/assets are never overwritten. `textApproved=false` and `designApproved=false` remain in the review ZIP. Provider success is covered with an injected test response; local library generation and browser export are real. A paid API generation was not run for acceptance.
