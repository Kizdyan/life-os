# Persona Media Worker — проверяемый архив одного проекта

Это **отдельное резервное копирование файлов локального Media Worker**. Оно не заменяет браузерный ZIP Persona и не отправляет файлы в облако. Команды выполняются на компьютере Windows, где хранятся исходники.

## Что сохраняется

Полная папка одного `quick-<UUID>` проекта: `job.json`, `quick-state.json`, все загруженные исходники в `input/`, монтажные планы, черновые и финальные MP4, платформенные файлы, JPEG/QC-отчёты и другие результаты в `output/`. Каждый обычный файл учитывается в `manifest.json` с его размером и SHA-256. Символьные ссылки, незаконченные задания и временные/заблокированные файлы запрещены; отсутствие файла вызывает ошибку, а не «успех без данных».

**Важно:** перед созданием и восстановлением копии **останови Media Worker** и дождись окончания рендера. Копию лучше создавать на другом физическом диске. Файлы могут содержать личные исходники и сценарии — храни архив конфиденциально.

## Windows PowerShell

Открой папку репозитория `Kizdyan/life-os`. UUID проекта виден в адресе локального файла/в данных проекта, например `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`.

```powershell
# Создать родительскую папку архива на внешнем диске:
New-Item -ItemType Directory -Force "E:\PersonaBackups"

# 1. Создать НОВУЮ папку с копией — её не должно быть заранее:
npm run persona:worker:backup -- backup "$env:LOCALAPPDATA\LifeOS\Persona\quick-renders" "<UUID>" "E:\PersonaBackups\Reel-001"

# 2. Самостоятельно проверить перенесённые файлы:
npm run persona:worker:backup -- verify "E:\PersonaBackups\Reel-001"

# 3. Восстановить проект в пустой Worker root (или при отсутствии этого UUID):
npm run persona:worker:backup -- restore "E:\PersonaBackups\Reel-001" "$env:LOCALAPPDATA\LifeOS\Persona\quick-renders"
```

Если в Worker задан `PERSONA_QUICK_RENDER_ROOT`, используй **тот же путь** в командах вместо `$env:LOCALAPPDATA\LifeOS\Persona\quick-renders`.

Восстановление **никогда не перезаписывает** папку существующего проекта. После восстановления в исходный путь запусти Worker и проверь список проектов и скачивание MP4. При переносе в новый путь Worker также должен быть запущен с соответствующим `PERSONA_QUICK_RENDER_ROOT`.

## Ограничения и что проверено

- `verify` проверяет имена, размеры и SHA-256 **каждого** файла; дополнительные или отсутствующие файлы вызывают ошибку. Это проверка целостности, **не криптографическое подтверждение авторства архива**. Восстанавливай только собственные доверенные архивы.
- При восстановлении в другом каталоге **существующие готовые MP4 доступны для чтения/скачивания**, но внутренние монтажные документы могут содержать абсолютные пути от старого компьютера. **Повторный рендер после переезда не подтверждён**, автоматической миграции таких путей нет.
- Это копия **одного проекта**, не всего диска и не всех проектов автоматически. Браузерные редакционные данные, Stories и IndexedDB-фотографии по-прежнему требуют отдельного ZIP.
- Архив не появляется автоматически в облаке и не создаётся сам при каждом выпуске; его нужно хранить отдельно от исходного диска.
- Скрипт никогда не удаляет исходные проекты, не выполняет публикацию, не меняет статус утверждения и не записывает токен Media Worker.
- Код ограничивает один архив 5000 файлами и 50 ГиБ. Если проект больше, резервное копирование завершится явной ошибкой без частичной «успешной» копии.

Технические проверки в `tools/persona-quick-job-backup.test.mjs` включают сохранность байтов, запрет перезаписи, повреждённые файлы и опасные пути. Существующий реальный FFmpeg-тест `tools/persona-quick-render.test.mjs` дополнительно проверяет восстановленный 1080p MP4 через второй Media Worker.
