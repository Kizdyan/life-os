# Persona — реальная вставка архивного B-roll в смонтированное видео

**Статус:** новая изолированная функция над PR #140. Работает локально через уже существующий FFmpeg renderer. Нет облачных запросов, нет отправки в соцсети, нет автоматической художественной приёмки.

## Зачем

Раньше Local Library и \`persona-library-shot-match.mjs\` только находили подходящий кадр и создавали отчёт \`ASSET-MATCHES.json\`. Между предложением и реальным рендером был разрыв. Новый \`persona-approved-broll.mjs\` добавляет в уже проверенный монтаж строго отобранный автором архивный фрагмент, сохраняет связь с исходным SHA и сдвигает последующие субтитры.

На первом этапе система **вставляет B-roll только МЕЖДУ полными произнесёнными репликами**. Она не заменяет актёрскую сцену архивом, не накрывает озвучку поверх B-roll и не пытается автоматически угадать точное место художественной склейки. Это осознанный безопасный первый вертикальный срез.

## Необходимые реальные входные данные

1. Из \`persona:flow prepare\` — реальный \`PRODUCTION-BRIEF.json\` и \`ASSET-MATCHES.json\`, привязанные к тому же сценарию.
2. Из \`persona:library scan\` — \`index/persona-assets-v1.json\`, содержащий физический корневой каталог, SHA и метаданные.
3. Из успешного \`persona:flow render\` или \`media:first-reel:draft\` — исходный \`timeline.json\` (из **ровно одного реального речевого клипа на каждый beat**).
4. Из того же исходного рендера — \`captions.review.json\` с реальными либо явно маркированными оценочными временны́ми метками. Уже готовые черновые subtitle sidecars не считаются авторски утверждёнными.

## 1. Создать безопасный шаблон выбора

Из корня репозитория:

    npm run persona:broll -- template "<ORIGINAL_TIMELINE.json>" "<ASSET-MATCHES.json>" "<persona-assets-v1.json>" "<captions.review.json>" "<NEW-selection.json>"

Шаблон перечисляет кандидатов: beat, asset ID, секунды, framing. Все кандидатуры неутверждённые, поля \`authorReviewed=false\`, \`rightsConfirmed=false\`, \`approvedForEdit=false\`. Команда НЕ создаёт видео и не производит автоматическое согласование.

## 2. Просмотреть кадр и сознательно подтвердить использование

Просмотрите **оригинал** в указанном временно́м диапазоне и проверьте художественную уместность, отсутствие неожиданного чужого материала, право использовать видео, звук, кадрирование и необходимость вставки.

Только после явного решения автора отредактировать выбор:

- \`author\` — имя/отметка автора;
- \`reviewedAt\` — фактическая ISO дата просмотра;
- \`approvedForEdit=true\` — разрешение **только на монтаж**;
- у каждого разрешённого выбора \`authorReviewed=true\`, \`rightsConfirmed=true\`, \`editorialReason\` (объяснение, зачем вставка);
- оставить только действительно утверждённые \`choices\`, сохраняя SHA-поля источников.

**Не менять \`publicationApproved=false\`.** Это отдельное решение, не выдаваемое данным инструментом. AI не должен самостоятельно заполнять флаги от лица пользователя.

Ограничения первого этапа: только настоящие архивные видео, до 1.9 секунды на одну вставку, не больше одной вставки после каждого beat, режим \`contain\` без агрессивного обрезания лиц или очков. Эти рамки нужны, чтобы не вставлять длинные куски тишины, которые текущий QA правильно считает дефектом.

## 3. Создать настоящий новый MP4

    npm run persona:broll -- render "<ORIGINAL_TIMELINE.json>" "<ASSET-MATCHES.json>" "<persona-assets-v1.json>" "<captions.review.json>" "<REVIEWED-selection.json>" "<NEW_RENDER_DIR>"

Инструмент:

- Сверяет SHA всех четырёх контрольных JSON, чтобы решение не относилось к устаревшей редакции.
- Проверяет, что каждый выбранный asset есть в настоящем match-report именно для выбранной сцены.
- Повторно считывает реальный файл с диска и сравнивает размер/SHA с индексом. Проверяет, что путь не вышел за пределы выбранной медиатеки.
- Проверяет, что временно́й фрагмент лежит внутри фактического источника и диапазона кандидата.
- Вставляет архивный клип строго после указанной полной реплики, не изменяя остальные клипы.
- При использовании B-roll заглушает **только звук архивного источника**; звук оригинальных реплик не меняется.
- Сдвигает все следующие caption cues на фактическую длительность вставок, создаёт новые \`captions.broll.draft.srt\` / \`.vtt\` и \`captions.broll.review.json\`.
- Вызывает существующий FFmpeg Timeline Renderer для создания **реального** MP4.
- Проверяет реальный результат через Persona Render QA (FFprobe + FFmpeg black/silence scan + SHA). При техническом провале оставляет \`FAILED.json\`.
- Сохраняет \`BROLL-RESULT.json\`, включая ссылки на файлы/оригиналы/решения и статус \`AWAITING_AUTHOR_REVIEW\`.

Результаты в новом каталоге:

    approved-broll-draft.mp4
    approved-broll-draft.mp4.persona.json
    approved-broll-timeline.json
    captions.broll.draft.srt
    captions.broll.draft.vtt
    captions.broll.review.json
    broll-qa.json
    BROLL-RESULT.json

Никакие предыдущие рендеры, исходные MOV или старые subtitle sidecars не перезаписываются.

## Что осталось на следующий этап

- Настоящий просмотр и утверждение выбора в интерфейсе Persona; пока безопасный отдельный JSON workflow.
- Умные B-roll overlays поверх речи с безопасной ducking-моделью, а не только вставки после реплик.
- Художественная QA актёрской игры и целостного монтажа по настоящим кадрам; текущая техническая QA этого не доказывает.
- Проверка на пользовательском Windows с настоящими файлами и локальным Media Worker.
- Пересчёт истории правок и исполнение через GUI, а затем отдельная публикация через реальные аккаунты.

Важно: ни успешный технический тест, ни \`approvedForEdit=true\` не разрешают публикацию. Система явно сохраняет \`distributionAllowed=false\` и \`publicationApproved=false\`.
