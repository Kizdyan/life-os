# Persona — от нескольких настоящих ИИ-идей к выбору автора

**Цель:** убрать скрытый выбор первой идеи из \`persona:flow prepare\` и дать автору оценить несколько самостоятельных концепций *до* генерации съёмочного сценария. Никаких фальшивых судей, статистики, публикаций и автоматического согласия автора.

## 1. Получить альтернативы от реальной модели

    npm run persona:ideas -- propose "Короткий ролик про актёрство и музыкальную режиссуру" "<NEW_PROPOSAL_DIR>" "docs/persona-model-servers.example.json" humor

Используется один реальный запрос к настроенному Ollama-compatible серверу (с теми же безопасными правилами URL/секретов, что и \`persona:flow\`). Валидируются 3–5 оригинальных, неповторяющихся идей.

Файлы:
- \`IDEAS.json\`: ID каждой идеи, название, хук, замысел, происхождение модели, статус \`AWAITING_AUTHOR_IDEA_SELECTION\`, \`publicationApproved=false\`;
- \`IDEAS.md\`: читаемые варианты для сравнения.

**Сценарий на этом этапе не создаётся.** Ни одна идея не выбирается автоматически. Если модели нет или она возвращает неверные данные — ошибка; никаких замен на шаблон.

## 2. Человек выбирает конкретную идею

Прочитай \`IDEAS.md\`. Выбери ID, например \`idea-3\`:

    npm run persona:ideas -- select "<NEW_PROPOSAL_DIR>\IDEAS.json" idea-3 "<NEW_PRODUCTION_DIR>" "docs/persona-model-servers.example.json" "<OPTIONAL persona-assets-v1.json>"

Используется **ровно один новый реальный запрос** к ИИ-режиссёру на развитие выбранной концепции. Альтернативы НЕ генерируются повторно. Получаются:

- \`PRODUCTION-BRIEF.json\` с \`ideaId=idea-3\`;
- \`SHOOT.md\` с действиями, текстом, светом и крупностями;
- \`FLOW.json\` с \`ideaSelectionMode=explicit_saved_candidate\`, выбранным ID и SHA-256 исходного файла идей;
- \`IDEAS.json\` в пакете производства, содержащий все исходные альтернативы и выбранный ID;
- при наличии индекса библиотеки — настоящие \`ASSET-MATCHES.json\` и \`SHOOT-GAPS.md\`.

Полученный план не разрешает публикацию и всё ещё требует реальной съёмки: \`WAITING_FOR_FOOTAGE\`.

Если указанной идеи нет, формат подменён, сохранённый файл не является валидным пакетом или целевая папка уже существует, процесс должен завершиться отказом до обращения к модели или создания новой папки.

## 3. Что остаётся совместимым

Старая команда \`npm run persona:flow -- prepare\` по-прежнему работает, не ломая ранее созданные сценарии. Но в \`FLOW.json\` она теперь честно помечается \`ideaSelectionMode=legacy_automatic_first\`: это не согласование автора и не независимое ИИ-судейство.

После \`select\` без изменений работают уже имеющиеся \`persona:flow render\`, Whisper, FFmpeg и библиотека. Предыдущий B-roll монтаж и офлайн-выбор архивных кадров из PR #141/#142 совместимы с новым планом.

## Ограничения

- Пока выбор по ID выполняется командой, а не кнопкой внутри браузерной Persona. UI необходимо связать с безопасным локальным Worker отдельно.
- ИИ-оценивание разных идей независимыми моделями ещё не реализовано и **не симулируется**.
- Изменяемый файл \`IDEAS.json\` — локальный пользовательский вход, не криптографически подписанное серверное доказательство. В производственном \`FLOW.json\` сохраняется SHA для воспроизводимости именно этой редакции.
- Не создаются оригинальные медиафайлы, соцпосты или публикации. Их наличие доказывают только реальные последующие фазы.
