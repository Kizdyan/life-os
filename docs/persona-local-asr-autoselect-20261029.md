# Persona: offline ASR → автоматический выбор дублей (29 октября 2026)

Это узкий дополнительный этап существующего конвейера; не новый видеоредактор и не готовый полноценный мультимодальный ИИ.

## Уже работает в коде

- tools/persona-semantic-autoselect.mjs: transcribe запускает внешний локальный whisper.cpp (whisper-cli) на WAV, которые ранее создал Persona analyze; модель не скачивается автоматически, платные API и сеть не используются.
- plan читает результат whisper.cpp JSON с таймкодами отдельных слов, сопоставляет с репликами существующего PersonaProductionBrief, выбирает наиболее полное совпадение среди нескольких дублей.
- Неуверенное или отсутствующее совпадение вызывает ошибку с требованием проверки человеком, а не случайную склейку.
- Выход decisions.json совместим с существующим tools/persona-semantic-montage.mjs assemble, который дополнительно проверяет SHA-256 исходников и их временные границы.
- Изменения проверены на тестовых транскриптах и синтетических видео; не объявлять эти проверки доказательством качества распознавания живой речи.

## Реальный маршрут на ПК

1. Записать только явно выбранные видео в sources.json по существующей схеме: version 1, sources (минимум 1, максимум 12 (для монтажа нужны не менее двух непересекающихся речевых фрагментов)), каждый источник с id и path.
2. Выполнить: node tools/persona-semantic-montage.mjs analyze sources.json ./evidence-new
3. Убедиться, что пользователь отдельно разрешил и предоставил локальные whisper-cli.exe и многоязычную (не .en) модель ggml-*.bin.
4. Выполнить: node tools/persona-semantic-autoselect.mjs transcribe ./evidence-new/analysis.json PATH_TO_WHISPER_CLI PATH_TO_LOCAL_MODEL
5. Выполнить: node tools/persona-semantic-autoselect.mjs plan ./evidence-new/analysis.json PATH_TO_PERSONA_BRIEF_JSON ./decisions-new.json
6. Просмотреть реплики/таймкоды. Выполнить: node tools/persona-semantic-montage.mjs assemble ./decisions-new.json ./timeline-new.json
7. Выполнить: node tools/persona-timeline-render.mjs ./timeline-new.json ./reel-new.mp4
8. Выполнить: node tools/persona-verify-render.mjs ./reel-new.mp4 reel-001 reel ./reel-qa.json
9. Просмотреть глазами и ушами монтаж; вручную поправить музыку, цвет, эмоции, очки, титры; только после авторского подтверждения готовить Instagram.

Официальная спецификация CLI whisper.cpp: https://github.com/ggml-org/whisper.cpp/blob/master/examples/cli/README.md . Используются опции -m, -f, -l auto, -ml 80, -sow, -ojf и -of. JSON с временными границами: transcription[].offsets.{from,to} в миллисекундах.

## Чего ещё нет

На Windows пока не проведён запуск настоящего whisper-cli на личных голосовых исходниках; тест использует имитированные ASR-таймкоды. Нет оценивания актёрской игры и выражения лица, выбора музыкального фрагмента, полной цветокоррекции, проверки субтитров и настоящего автоматического согласования публикации. Для B03 длительность музыкального хвоста теперь сохраняется по явной ремарке shots[].action и сценарию; слуховой контроль реальной музыки по-прежнему обязателен. Нет пользовательской кнопки для этого модуля в интерфейсе, пока работает только Node CLI в изолированном Draft PR.

Не добавлять глобальный PATH, не устанавливать неизвестные исполняемые файлы и не отправлять голос/лицо во внешние модели без отдельного разрешения. Существующий FFmpeg уже проверен в Windows; его не переписывать.

Критерий следующей проверки: реальные разрешённые дубли → локальный Whisper → выбор корректных реплик → реальный MP4 из этих файлов → визуальный QA → авторское утверждение.


## Единый запуск (вместо пяти команд)

Для пользователя, выбравшего исходники, локальный whisper.cpp и модель, добавлен оркестратор:

node tools/persona-first-reel-runner.mjs SOURCES_JSON PERSONA_BRIEF_JSON NEW_OUTPUT_DIRECTORY WHISPER_CLI_PATH MODEL_BIN_PATH [PORTABLE_FFMPEG_BIN_DIRECTORY]

Например, в пользовательской рабочей папке с собственными роликами задать два JSON и разрешённую заранее локальную модель. Оркестратор выполняет существующие analyze → transcribe → plan → assemble → persona-timeline-render → persona-verify-render. Результат: NEW_OUTPUT_DIRECTORY/draft-reel.mp4, timeline.json, decisions.json, qa.json, RESULT.json и материалы evidence. Итоговый статус всегда awaiting-author-review, распространение не разрешено, исходники не перезаписываются. Системный PATH не меняется: необязательная папка portable FFmpeg временно добавляется только в окружение текущего процесса и его дочерних команд.

Команда npm: npm run media:first-reel:draft -- SOURCES_JSON BRIEF_JSON NEW_OUTPUT_DIRECTORY WHISPER_CLI MODEL_BIN PATH_TO_FFMPEG_BIN

При сбое частичные файлы остаются для диагностики и появляется FAILED.json. Повторно использовать уже существующую выходную директорию нельзя. Юнит-тест оркестратора с имитацией ASR/рендерера/QA проверяет последовательность и сохранность оригиналов. Отдельный last-mile smoke вызывает реальный FFmpeg-рендерер и реальный QA, подменяя только ASR-таймкоды. Ни тот ни другой тест не доказывает точность настоящей модели Whisper или художественную пригодность ролика.

Доступность реального whisper-cli и многоязычной модели в Windows пользователем/исполняющей средой ещё не подтверждена. Их подключение требует отдельного разрешения; если отсутствуют — скрипт отказывается выполнять «псевдо-автомонтаж».


## Проверка технического качества дублей ДО монтажа

Добавлена независимая диагностика tools/persona-take-qa.mjs, автоматически вызываемая в существующем analyze на каждом разрешённом исходнике. FFmpeg измеряет среднюю яркость и насыщенность по редким временным пробам, интервалы полностью чёрного изображения и аудиопик. Результат сохраняется в поле analysis.json.sources[].technicalQuality с предупреждениями. Никаких фильтров, изменений кожи, внешности или исходников не применяется.

- Если реплика совпадает по ASR, но выбранный временной интервал пересекается с обнаруженными чёрными кадрами, планировщик исключает этот дубль. При отсутствии чистой альтернативы честно требует ручной проверки.
- Сигнальные предупреждения о темноте/пересвете и близости звукового пика к 0 dBFS **не являются доказательством низкого художественного качества**, не запускают автоматическую цветокоррекцию и не влияют на оценку актёрской игры. Критерий выбора пока ограничен речью и отсутствием чёрных фрагментов.
- На реальном присланном видеореференсе (44,7 с) отдельно проверен скан: 45 временных проб яркости, чёрных интервалов не обнаружено, аудиопик 0 dBFS отмечен к ручной проверке. Это **референс, не собственный Reel автора**.
- Регрессионные тесты проверяют парсер объективных сигналов, исключение чёрного временного окна, реальный синтетический чёрный MP4 и сохранность его исходника.
- Путь процесса: анализ видео → технические свойства → Whisper (только при наличии реальной локальной модели) → выбор целого речевого дубля без чёрных интервалов → уже существующий FFmpeg → QA → авторское утверждение.


## Совместимость JSON-full с токенами whisper.cpp (29.10.2026)

Проверен upstream исходник `ggml-org/whisper.cpp` `examples/cli/cli.cpp`: у сегментов присутствуют `offsets.from/to` в миллисекундах, а отдельные элементы `tokens[]` **могут не иметь своих offsets**. Ранее Persona в таком случае теряла всю реплику. Исправлено: при отсутствии хотя бы части токенных таймкодов используем таймкод и текст полного сегмента, не выдумывая точность по словам. Когда таймкоды токенов есть, обрывки русского слова без ведущего пробела объединяются в одно слово, чтобы не допускать ложного несовпадения с исходным сценарием.

Добавлены три регрессионных теста на отсутствующие/частичные токенные offsets и русские subword-токены. Локальный Node/FFmpeg набор в отдельном окружении: **18 тестов пройдено, 0 ошибок**, на синтетических исходниках и подставных ASR-данных. Настоящая Windows-модель whisper.cpp пока не проверена на голосе пользователя. Полная GitHub CI остаётся отдельным обязательным условием интеграции.

Если модель отдаёт только грубые таймкоды длинной реплики, интеллектуальный подбор может потребовать ручной редакторской проверки, вместо попытки выдать приблизительный разрез за точный.

## Исправление: сохранять действие после реплики (29.10)

В первом семикадровом Reel реплика «Почему? Сейчас напишу колыбельную.» переходит в **2–3 секунды оригинальной музыки**. Обычный ASR распознаёт только слова и обрезает музыкальный хвост. Планировщик теперь использует уже существующее указание в `shots[].action`: если там явно сказано о музыке **после реплики**, предложенный интервал длится не меньше запланированной `shots[].durationSec`. Если исходник слишком короткий либо удерживаемый фрагмент попадает на чёрные кадры, автоматический монтаж **останавливается для проверки**, не маскируя дефект. Остальные речевые планы не растягиваются автоматически.

CLI Whisper скорректирован в соответствии с его документированными аргументами: `-ml 80 -sow -ojf` вместо `-ml 1` (один символ — не одно слово). Это уменьшает ненужное дробление русских слов на однобуквенные сегменты. **Точность реальной многоязычной модели Whisper на Windows всё ещё не проверена.**

Локальная регрессия с синтетическими таймкодами: музыкальный хвост сохраняется; недостаточный исходник и чёрный интервал блокируют автоматическое решение. Полный локальный набор из 19 тестов прошёл после изменений; GitHub CI необходимо проверить отдельно.

## Один архивный видеоролик → несколько сцен (29 октября 2026)

Для первого Reel больше **не нужно искусственно записывать два разных файла**. В `sources.json` может быть один явно выбранный автором файл, если в нём реально содержатся необходимые реплики и сцены. `analyze` принимает 1–12 источников, `plan` умеет находить несколько непересекающихся интервалов одного источника, а существующий рендерер по-прежнему требует минимум 2 **монтажных фрагмента**, не минимум 2 видеофайла.

`assemble` теперь дополнительно отвергает пересекающиеся исходные интервалы с одним `sourceId`, даже если исполняемый редактор или ИИ обошли обычный планировщик, сохраняя неизменность оригинала и блокируя создание timeline при ошибке. На 5-секундном синтетическом MP4 проверены анализ одного файла → два отдельных решения → один JSON с двумя сценами → отсутствие изменений оригинала. На тестовых таймкодах проверено автоматическое выделение двух реплик из одной длинной записи.

В текущем PR также добавлен `tools/persona-last-mile-smoke.test.mjs`: это новая **не прошедшая здесь полный запуск** интеграционная проверка с **реальным** `persona-timeline-render.mjs` и **реальным** `persona-verify-render.mjs`; только ASR остаётся тестовой заглушкой. В отличие от раннего smoke test со stub-рендерером, её цель — подтвердить настоящий H.264/AAC MP4, технические проверки и закрытый publication gate. Её выполнение ожидает полного локального checkout проекта / штатного GitHub CI; не объявлять пройденной заранее.

**Локально повторённые проверки модулей:** 21/21 Node-тест прошёл; отдельно подтверждены одноклиповый анализ/монтажный проект, отказ от пересечений и сохранность исходного MP4. Никакого реального русского Whisper на пользовательских материалах или готового Reels для публикации пока нет.

## Проверка fail-closed после реального рендера (29.10.2026)

`persona-first-reel-runner.mjs` теперь проверяет структуру и результат `qa.json` перед записью `RESULT.json`:
- техническое доказательство относится к **тому же** пути MP4, содержит SHA-256, положительный размер/длительность, 1080×1920, ровно 30 fps, H.264/AAC и положительные проверки чёрных кадров и звука;
- в `handoff` ровно один ожидаемый блокер `author approval required`, остальные проверки актива должны быть пройдены; `distribution` обязан оставаться `null`;
- некорректные результаты или внезапное разрешение дистрибуции приводят к `FAILED.json`, а не к ложному статусу готовности к авторскому просмотру.

Добавлены unit-регрессии на пропущенный блокер публикации, ошибку чёрных кадров, некорректный FPS, посторонний путь MP4 и неожиданный разрешённый статус. **Новые коммиты ещё не прошли CI**, поэтому это контроль в коде, не подтверждённая Windows-приёмка.

### Текущие блокеры для реального выпуска
1. Выбрать принадлежащий автору исходный MP4 и рабочий `PersonaProductionBrief`.
2. Подтвердить существующие в Windows локальные `whisper-cli.exe` и **многоязычную** модель, затем запускать единую команду на новых выходных путях.
3. Просмотреть экспорт глазами и ушами, особенно русскую речь, музыку в B03, цвет и мимику. Никаких скрытых коррекций внешности.
4. GitHub Actions на последнем проверенном до этих изменений коммите завершался **до первого шага**; Vercel отмечал ограничение сборок. Причину Actions нельзя считать установленной без диагностик инфраструктуры. Нельзя сливать Draft PR в `main` по одному локальному тесту.

## Готовый семикадровый бриф и запуск из одного MP4 (29.10.2026)

В эту же ветку перенесён **без изменения содержимого** ранее подготовленный черновик из PR #125:
`docs/persona-first-reel-production-brief-2026-10-29.json` — семь реплик и семь кадров, 31 секунда проектного тайминга. Бриф не является утверждённой съёмкой; он нужен, чтобы не создавать вручную новый JSON перед первым тестом. Фактическая длина монтажа будет зависеть от выбранных ASR-интервалов; без реальной записи и просмотра 31 сек не гарантируются.

Теперь вместо `sources.json` разрешено явно выбрать **один локальный** `.mp4/.mov/.mkv/.webm/.m4v` файл. Оркестратор создаст **только для него** `NEW_OUTPUT_DIRECTORY/sources.generated.json`, не сканируя папки и не выбирая другие медиа. В самом видео должны прозвучать **все семь** сценарных реплик (или использовать собственный адаптированный бриф хотя бы с двумя репликами); при пропущенной реплике автоматический выбор останавливается.

Запуск из корня проекта (пути к видео, модели и Whisper заменить на свои; каталог результата должен быть новым):

```powershell
npm run media:first-reel:draft -- "D:\\PersonaMedia\\approved-source.mp4" "docs/persona-first-reel-production-brief-2026-10-29.json" "D:\\PersonaMedia\\draft-001" "D:\\Tools\\whisper.cpp\\whisper-cli.exe" "D:\\Models\\ggml-base.bin" "D:\\Tools\\ffmpeg\\bin"
```

Указанная в примере многоязычная модель — **пример пути**, не свидетельство её наличия на ПК и не рекомендация скачивать что-либо автоматически. Portable FFmpeg указывается необязательно, если команды уже доступны процессу.

После успеха проверить `draft-001/draft-reel.mp4`, `draft-001/qa.json`, `draft-001/decisions.json` и `draft-001/RESULT.json`. Статус — строго `awaiting-author-review`; никаких публикаций.

Контракт дополнительно проверяется новым интеграционным smoke-тестом: **один синтетический MP4** с двумя непересекающимися репликами-фикстурами → автоматически созданный manifest → реальный FFmpeg renderer → настоящий media QA, без изменения входного видео. Добавлена проверка структуры семикадрового брифа. Эти тесты после добавления **пока не подтверждены успешной GitHub CI или Windows-сборкой**.

Показанные пути `D:\\...` иллюстративные. Ни исходное пользовательское видео, ни модель Whisper не обнаружены и не установлены в ходе этого изменения.
