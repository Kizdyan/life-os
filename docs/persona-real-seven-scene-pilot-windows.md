# Persona · один реальный 7-сценный пилот на Windows

**Стадия:** локальный технический пилот, не продакшн-публикация. Работать в **отдельном worktree** коммита PR #147; не переключать рабочее дерево Codex, не менять оригинальные MOV, не мержить PR.

## Что действительно происходит

Первая команда на **реальных локальных** видео запускает существующие FFmpeg/Whisper и создаёт либо проверяемый, но **неутверждённый** `draft-reel.mp4`, либо Recovery Review (без MP4). После этого автоматически готовится локальная HTML-страница для прослушивания и сравнения дублей. До и после каждого этапа сверяются SHA-256 источников и утверждённого Production Brief.

Вторая команда принимает **только** просмотренный и сохранённый в HTML `selection.reviewed.json`, создаёт **новый** MP4 с выбранными дублями и отдельный `VIDEO-QUALITY.json` на финальном файле. Не изменяет предыдущий черновик, не публикует. Качество актёрской игры, очков/лица, музыки и естественность цвета — исключительно авторская приёмка.

Для первой попытки используется утверждённый семисценный файл `docs/persona-first-reel-production-brief-2026-10-29.json`. Последняя реплика целиком: **«Это колыбельная? Это финал триллера.»** В B03 обязательно услышать паузу и собственную музыку **после** речи.

## Подготовка

Нужны Windows, Node.js 22+, локальные FFmpeg/FFprobe, нативный `whisper-cli.exe`, multilingual `ggml` модель и выбранные реальные исходники (например, семь именованных файлов A01/B01/A02/B02/A03/B03/A04 или два длинных ролевых дубля; снимки не подменяются). Используйте путь, где уже лежат реальные исходники. Создайте отдельный worktree **не меняя открытую ветку Codex**:

```powershell
# Выполняется один раз из существующей локальной копии life-os
git fetch origin fix/persona-manual-verbatim-b04-20261104
git worktree add --detach "C:\Persona\life-os-pilot" FETCH_HEAD
Set-Location "C:\Persona\life-os-pilot"
```

В PowerShell **из корня нового worktree**:

```powershell
npm ci
npm run persona:preflight
npm run persona:pilot -- start "C:\Persona\Originals" "C:\Persona\Pilot-01-Draft" "C:\Tools\whisper\whisper-cli.exe" "C:\Tools\whisper\models\ggml-medium.bin"
```

Если FFmpeg не в PATH, добавьте последним аргументом каталог, содержащий `ffmpeg.exe` и `ffprobe.exe`. Папка `Pilot-01-Draft` **не должна существовать** до запуска; она должна находиться **вне папки исходников**.

### Важная проверка B03 и B04

- **B03 — «Почему? Сейчас напишу колыбельную.»**: после слов должна остаться именно оригинальная музыка из выбранного дубля, а не отдельный сгенерированный звук. Если Whisper дал только приблизительные сегментные таймкоды, автоматический дубль отклоняется. При ручном Recovery Review нужно указать в браузере **абсолютную секунду окончания последнего слова в исходном видео**, внутри выбранного фрагмента и до музыкального хвоста. Если на слух нельзя установить границу либо музыки в оригинале нет — остановить сборку и переснять/перезаписать исходник. Не выдумывать границу.
- При выборе дубля B03 сохранённая разметка передаётся в FFmpeg; коррекция громкости речи не должна перезаписывать естественную громкость музыкального хвоста. Черновой SRT заканчивает реплику не позже указанной границы. Проверка звука в финальном MP4 всё равно обязательна.
- **B04 — целиком «Это колыбельная? Это финал триллера.»**. В строгой сборке фраза проверяется в полном виде; «Эта колыбельная», отсутствие второй части, добавленные слова и перестановка слов недопустимы. Субтитры не могут подменять реально произнесённую реплику.
- Если HTML-страница создана **до обновления** этих проверок, создайте новый Draft-пилот в новом каталоге, чтобы ручной JSON содержал границу B03 и соответствовал актуальному редактору.

После команды откройте путь из `PILOT.md` (он появится в папке черновика) или `PILOT.json → reviewHtml`. Каждую реплику и дубль проверьте на слух и визуально. Если ASR ошибся — Recovery Review; если неверно **произнесён** текст — пересъёмка, а не подмена субтитров. В браузере сохраните `selection.reviewed.json`. Если исходный ASR дал Recovery, CLI завершится с кодом 2: **это ожидаемая остановка**, а не успешный рендер.

## После выбора дублей

```powershell
npm run persona:pilot -- resume "C:\Persona\Pilot-01-Draft" "C:\Users\YOU\Downloads\selection.reviewed.json" "C:\Persona\Pilot-01-Reviewed"
```

Новый каталог также должен отсутствовать до запуска. Полученные файлы: `reviewed-reel.mp4`, `reviewed-qa.json`, `VIDEO-QUALITY.json`, `PILOT-REVIEWED.md`, `PILOT-REVIEWED.json`, `creative-review.json` и draft SRT. По отчёту проверьте все предупреждения и не измеренные свойства. Визуально просмотрите **весь MP4**, сравните оба роли, цвет кожи, белую футболку, очки и глаза, свет, синхронность субтитров, баланс речи/музыки, паузы и финальную шутку.

**Доказательство завершения этого этапа:** реальный MP4 с SHA-256, читаемыми QA, 7/7 вручную проверенными репликами и заполненной художественной ревизией. Даже после технического успеха остаются `publicationApproved=false`, `distributionAllowed=false`: отдельное явное разрешение на публикацию не входит в пилот.

**Здесь из облачного GitHub не доступен Windows-диск и исходные съёмки.** Синтетический CI демонстрирует корректность инструментов, но не доказывает, что реальный пилот уже прошёл. Не указывать статус `real Windows E2E PASS` до настоящего запуска и просмотра.
