> Срез на 2026-11-02. Это карта **доказательств**, а не оценка готовности в процентах. Для нового SHA результаты CI необходимо проверять заново.

## Что является продуктом

**Первая полезная версия (V1):** пользователь создаёт сценарий и Production Brief, проверяет реальный MP4, получает три локальных цветовых варианта, видит исходник и обработку, выбирает вариант с комментарием и после перезагрузки видит сохранённое решение. Авторское решение не разрешает публикацию.

**Долгосрочная Persona:** автоматизированное производство Reels от идеи до монтажа и финальной художественной проверки. Она **не** равна Comparison Studio; готовность всех её подсистем пока не доказана.

## Совместимость смартфонного видео: до первого испытания

**Текущие реальные ограничения CLI** (это не обещание совместимости с любым исходником):

- Вход: файл с настоящим контейнером **`.mp4`**, **SDR** (не HDR / PQ / HLG / BT.2020), размер от 1 КиБ до **160 МиБ**. Расширение `.mov` отклоняется, даже если внутри H.264.
- Видеопоток с ненулевым поворотом в metadata, встроенные subtitle streams, отсутствие видео и неподдерживаемые звуковые кодеки могут остановить рендер. Ошибка FFmpeg не означает повреждения оригинала.
- **Не переименовывайте** `.MOV` в `.mp4` вручную: изменение расширения не преобразует контейнер и не исправляет ориентацию.
- На поддерживаемых iPhone для **новой тестовой съёмки** можно отключить HDR: «Настройки» → «Камера» → «Запись видео» → «HDR-видео». Настройка «Камера» → «Форматы» → «Наиболее совместимый» выбирает H.264 для будущих видео, **но не гарантирует расширение `.mp4`**. Источники: [Apple — HDR](https://support.apple.com/ru-ru/guide/iphone/iphc1827d32f/27/ios/27), [Apple — H.264](https://support.apple.com/en-gb/116944).
- Для первого опыта достаточно **короткого вертикального SDR-фрагмента** с хорошо видимыми кожей, очками и освещением. Если запись получилась `.MOV` либо HDR, сначала потребуется **отдельный проверенный экспорт в SDR MP4**, причём исходник нужно сохранить без изменений. Никакого автоматического tone mapping в V1 нет.
- Прежде чем начинать рендер, можно посмотреть параметры видео:
  ```powershell
  ffprobe -v error -select_streams v:0 -show_entries "stream=codec_name,width,height,color_transfer,color_primaries" -of default=nw=1 "C:\\Videos\\my-reel.mp4"
  ```
  Отсутствие полей color_transfer/primaries не доказывает SDR; окончательное решение принимает проверка CLI, а спорные случаи требуют ручной проверки.

## Первый реальный Reels на Windows: короткая инструкция

Предварительные условия: Node.js и FFmpeg/FFprobe доступны из терминала, исходный файл **разрешён пользователем для этого испытания**, обычный SDR MP4 без встроенных soft subtitles и metadata-поворота, каждый MP4 после обработки — не более 160 МиБ.

1. Откройте терминал в корне Life OS и выполните (подставьте свои пути):
   ```powershell
   node tools/persona-color-variants.mjs "C:\\Videos\\my-reel.mp4" "C:\\Videos\\persona-compare-001"
   ```
2. Команда создаёт **новую** папку с `COMPARISON.json`, копией исходника и тремя обработанными MP4. Исходник по старому пути остаётся нетронутым. При повторном запуске используйте **новую папку назначения**.
3. Откройте Persona на `localhost` или HTTPS, выберите проект Reels → **Монтаж** → Comparison Studio → **Импорт результатов сравнения**; выделите одновременно все пять файлов из новой папки.
4. Посмотрите оригинал и варианты, сравните одинаковые участки, выберите один цветовой вариант и сохраните **комментарий с конкретными наблюдениями** (кожа, очки, свет, детализация, звук).
5. Перезагрузите страницу: авторский выбор должен сохраниться. MP4 не сохраняются в браузере — чтобы просмотреть повторно, снова выберите те же пять файлов.

Эта инструкция — **путь первого испытания, а не автоматический экспорт Reels**. Синтетический Chrome E2E не заменяет авторский просмотр реального видео. При HDR/PQ/HLG, soft subtitles или повороте в metadata локальный renderer должен безопасно отклонить исходник.

## Границы безопасности и честности

- Нет автоматической публикации и автоматического художественного одобрения.
- SHA-256 подтверждает идентичность файлов, **не** кинематографичность результата.
- Исходный MP4 не перезаписывается. Цветовые пресеты не изменяют геометрию и не выполняют генеративную ретушь.
- Подтверждённые данные, авторские оценки и гипотезы о стиле хранятся и описываются раздельно.
- Stacked PR #138 основан на PR #137; оба Draft. Зелёный CI **не означает**, что изменения уже внедрены в `main`.
