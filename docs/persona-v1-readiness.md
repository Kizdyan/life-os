## Что является продуктом

**Первая полезная версия (V1):** пользователь создаёт сценарий и Production Brief, проверяет реальный MP4, получает три локальных цветовых варианта, видит исходник и обработку, выбирает вариант с комментарием и после перезагрузки видит сохранённое решение. Авторское решение не разрешает публикацию.

**Долгосрочная Persona:** автоматизированное производство Reels от идеи до монтажа и финальной художественной проверки. Она **не** равна Comparison Studio; готовность всех её подсистем пока не доказана.

## Совместимость смартфонного видео: до первого испытания

**Текущие реальные ограничения CLI** (это не обещание совместимости с любым исходником):

- Вход: файл с настоящим контейнером **`.mp4`**, **SDR** (не HDR / PQ / HLG / BT.2020), размер от 1 КиБ до **160 МиБ**. Расширение `.mov` отклоняется, даже если внутри H.264.
- Видеопоток с ненулевым поворотом в metadata, встроенные subtitle streams, отсутствие видео и звук не в AAC остановят рендер до создания папки результата. Ошибка FFmpeg не означает повреждения оригинала.
- **Не переименовывайте** `.MOV` в `.mp4` вручную: изменение расширения не преобразует контейнер и не исправляет ориентацию.
- На поддерживаемых iPhone для **новой тестовой съёмки** можно отключить HDR: «Настройки» → «Камера» → «Запись видео» → «HDR-видео». Настройка «Камера» → «Форматы» → «Наиболее совместимый» выбирает H.264 для будущих видео, **но не гарантирует расширение `.mp4`**. Источники: [Apple — HDR](https://support.apple.com/ru-ru/guide/iphone/iphc1827d32f/27/ios/27), [Apple — H.264](https://support.apple.com/en-gb/116944).
- Для первого опыта достаточно **короткого вертикального SDR-фрагмента** с хорошо видимыми кожей, очками и освещением. Если запись получилась `.MOV` либо HDR, сначала потребуется **отдельный проверенный экспорт в SDR MP4**, причём исходник нужно сохранить без изменений. Никакого автоматического tone mapping в V1 нет.
- Прежде чем начинать рендер, можно посмотреть параметры видео:
  ```powershell
  ffprobe -v error -select_streams v:0 -show_entries "stream=codec_name,width,height,color_transfer,color_primaries" -of default=nw=1 "C:\\Videos\\my-reel.mp4"
  ```
  Отсутствие полей color_transfer/primaries не доказывает SDR; окончательное решение принимает проверка CLI, а спорные случаи требуют ручной проверки.

## Первый реальный Reels на Windows: короткая инструкция

Предварительные условия: Node.js и FFmpeg/FFprobe доступны из терминала, исходный файл **разрешён пользователем для этого испытания**, обычный SDR MP4 без встроенных soft subtitles и metadata-поворота, каждый MP4 после обработки — не более 160 МиБ.

**Важно:** в текущем `main` нет `tools/persona-color-variants.mjs`. Команду следует запускать из **отдельной тестовой копии** ветки PR #138, иначе файл не найдётся. Не переключайте свою рабочую Life OS на экспериментальную ветку.

1. В PowerShell откройте **существующую** локальную папку репозитория Life OS, а затем создайте отдельный Git worktree (новая папка рядом с существующей; имя можно изменить, если такое уже занято):
   ```powershell
   # Подставьте фактический путь к вашей существующей папке Life OS.
   Set-Location "D:\\path\\to\\life-os"
   git fetch origin feat/persona-comparison-studio-20261102
   git worktree add --detach "..\\life-os-persona-v1-test" FETCH_HEAD
   Set-Location "..\\life-os-persona-v1-test"
   Test-Path ".\\tools\\persona-color-variants.mjs"
   ```
   Ожидаемое значение `Test-Path` — `True`. `git worktree` не переименовывает и не заменяет существующие папки, не делает merge и не публикует изменения. Если fetch или worktree завершился ошибкой — остановитесь и проверьте сообщение вместо удаления папок.
2. Проверьте доступность инструментов и запустите рендер на **копии/исходнике, который вы сами выбрали** (папки подставьте свои):
   ```powershell
   node --version
   ffmpeg -version
   ffprobe -version
   node .\\tools\\persona-color-variants.mjs "C:\\Videos\\my-reel.mp4" "C:\\Videos\\persona-compare-001" "C:\\Users\\Kostya\\Tools\\FFmpeg\\ffmpeg-9.0.2-essentials_build\\bin"
   ```
3. Третий параметр необязателен, если `ffmpeg` и `ffprobe` уже находятся в `PATH`; на данном Windows-компьютере он передаёт их установленную папку явно. Команда создаёт **новую** папку с `COMPARISON.json`, копией исходника и тремя обработанными MP4. Исходник по старому пути остаётся нетронутым. При повторном запуске используйте **новую папку назначения**.
4. Откройте Persona на `localhost` или HTTPS, выберите проект Reels → **Монтаж** → Comparison Studio → **Импорт результатов сравнения**; выделите одновременно все пять файлов из новой папки.
5. Посмотрите оригинал и варианты, сравните одинаковые участки, выберите один цветовой вариант и сохраните **комментарий с конкретными наблюдениями** (кожа, очки, свет, детализация, звук).
6. Перезагрузите страницу: авторский выбор должен сохраниться. MP4 не сохраняются в браузере — чтобы просмотреть повторно, снова выберите те же пять файлов.

Эта инструкция — **путь первого испытания, а не автоматический экспорт Reels**. Синтетический Chrome E2E не заменяет авторский просмотр реального видео. При HDR/PQ/HLG, soft subtitles или повороте в metadata локальный renderer должен безопасно отклонить исходник.

## Границы безопасности и честности

- Нет автоматической публикации и автоматического художественного одобрения.

- Исходный MP4 не перезаписывается. Цветовые пресеты не изменяют геометрию и не выполняют генеративную ретушь.
- Подтверждённые данные, авторские оценки и гипотезы о стиле хранятся и описываются раздельно.
- Stacked PR #138 основан на PR #137; оба Draft. Зелёный CI **не означает**, что изменения уже внедрены в `main`.

## Video Quality Lab: сравнительный QC после рендера

Для готовой папки с COMPARISON.json, исходной копией MP4 и тремя обработками выполните:

```powershell
npm run media:comparison:qc -- "C:\Video\comparison-v2-natural-balanced" "C:\Video\comparison-v2-quality.json" "C:\Tools\ffmpeg\bin"
```

Аргумент ffmpeg\bin необязателен, когда FFmpeg/FFprobe уже в PATH. JSON-отчёт должен иметь НОВОЕ имя. Рядом создаётся папка comparison-v2-quality-frames с JPEG-парами: ORIGINAL слева, обработка справа. Исходный MOV не читается и не изменяется; инспектируется только MP4-копия внутри пакета.

QC проверяет SHA-256 всех четырёх файлов, полное декодирование, геометрию, FPS, длительность, аудиокодек, относительные изменения яркости/цветности и подозрительные скачки по выборке 4 кадра/с. A/B-кадры создаются на нескольких равномерных таймкодах и в местах дополнительных подозрительных скачков. Поскольку источник IMG_3971.MOV имеет 1072×1904, его MP4-копии должны сохранять 1072×1904; этот QC НЕ масштабирует в 1080×1920.

Технический статус PASS/FAIL не означает художественную приёмку. Поля artisticStatus=awaiting-author-review и publicationApproved=false обязательны. Статистические изменения не доказывают недостатки цвета кожи, света, актёрской игры или монтажа. Частота 4 fps не позволяет исключить быстрый фликер. JPEG-пары дополняют, но не заменяют сравнение видео в движении.

Сравнительный анализ использует существующий persona-video-quality.mjs, не вводя параллельную модель качества. На длинных исходниках он может выполняться долго, потому что проверяет полное декодирование четырёх MP4. Следующий этап — интерфейсный импорт отчёта, история ручных художественных решений и только затем адаптивные пресеты на подтверждённых референсах.

После выполнения CLI в Comparison Studio сначала импортируйте исходные пять файлов, затем отдельно — новый JSON-отчёт через «Выбрать технический QC-отчёт». Импорт отчёта допускается только при совпадении SHA-256 оригинала и всех трёх обработок; технические метрики показываются рядом с видео, но выбор и публикация остаются за автором. Последние 20 авторских решений по одному неизменному набору файлов сохраняются в истории проекта. Старые решения без истории остаются читаемыми.

### Расширенная проверка временной стабильности

Video Quality Lab теперь дополнительно берёт до 12 выборок яркости в секунду из исходного MP4 и каждого грейда, сопоставляет кадры по реальным временным меткам и ищет подозрительные изменения **разности** яркости между обработкой и оригиналом. Это уменьшает число ложных тревог от обычной монтажной склейки: если в оригинале произошёл большой перепад, он не считается доказательством нового фликера из-за пресета.

В отчёте: `variants[].temporalFlicker` со статусом `measured`/`not_measured` и ограниченным списком таймкодов. Comparison Studio показывает этот список после SHA-проверенного импорта отчёта; кнопка таймкода переключает нужный пресет и ставит оба видеоплеера в соответствующую точку.

Ограничения: 12 кадр/с не исключают мерцание выше примерно 6 Гц, отдельные ложные срабатывания возможны при движении и смене освещения. Этот анализ **не измеряет эстетическое качество и не ставит технический FAIL**. Недоступность временных выборок отображается как `not_measured`, а не как отсутствие проблем. Для реальной приёмки требуется просмотр видео в движении, в том числе в исходном разрешении.

## Художественная приёмка: выбор, отклонение и замечания к кадрам

После успешного реального QC по `IMG_3971.MOV` технический статус `PASS` **не** завершает художественную приёмку и не одобряет публикацию. В Comparison Studio после импорта пяти файлов можно либо сохранить выбранный цветовой вариант, либо **отклонить все три обработки**. Для отклонения обязательно укажите конкретную причину в поле комментария. Нельзя принять и отклонить все три варианта одновременно.

Кнопка «Зафиксировать замечание по текущему кадру» сохраняет выбранный пресет, таймкод оригинального видеоплеера, аспект (кожа, очки, свет/цвет, детали, движение, звук, другое), положительное или проблемное наблюдение, комментарий и время фиксации. До 30 последних замечаний привязываются к текущим SHA-256 оригинала и трёх обработок. Они восстанавливаются после перезагрузки без хранения MP4 в браузере. Пользователь может перейти к соответствующему кадру только после повторной проверки пяти файлов.

История хранит до 20 последних решений (включая отказы). Старые проекты без этих полей остаются читаемыми. При новом исходнике или изменившемся варианте выбор, отказ и замечания **не переносятся**. Технический PASS, положительная заметка, выбор обработки или отказ от всех вариантов не разрешают публикацию.

На исходнике `IMG_3971.MOV` Codex сообщил технический QC `PASS`, однако визуальная оценка цвета кожи и художественная приёмка остаются `AWAITING_AUTHOR_REVIEW`. Пока пользователь не оценил реальные кадры и MP4, **не изменяйте** сами цветовые формулы пресетов без подтверждённых визуальных причин.

## Экспорт замечаний для следующей итерации V3

После художественного просмотра сохраните выбор, отказ от всех вариантов либо отдельные замечания с таймкодами. Нажмите **«Скачать художественные замечания для Codex (JSON)»**. Файл `PERSONA-REVIEW-<12 символов SHA>.json` загружается только в локальную папку загрузок браузера, без сетевых запросов.

Этот переносимый `persona-color-review-brief-v1` содержит SHA-256 исходной MP4-копии и трёх пресетов, действующие формулы фильтров, решение автора и заметки (пресет, точный таймкод, аспект, оценка, текст). Не содержит видео, JPEG, абсолютных путей, секретов, готового разрешения публикации или утверждения, что цвета объективно хороши. `publicationApproved=false` независимо от выбора автора.

Для нового прохода Codex сначала сверяет SHA с локальным манифестом, затем выстраивает конкретный список улучшений по замечаниям и предлагает V3 в **новой** папке, не переписывая V2 и не изменяя оригинальный MOV. Нельзя автоматически править пресеты или публиковать материалы только из-за наличия экспортированного JSON.

Старые сохранённые записи Comparison Studio продолжают работать без обязательного экспорта. Отказ всех вариантов требует причины и сохраняется вместе с предыдущими решениями; его можно заменить последующим осознанным выбором. Экспорт поддерживает работу даже после перезагрузки браузера, когда сами MP4 уже не сохранены.

**Точность аннотаций и защита сохранения.** Таймкод художественного замечания снимается с активного **обработанного** MP4-плеера (того кадра, который автор оценивает); оригинальный плеер автоматически ставится в ту же точку. Привязка к SHA-256 обязательна не только для выбранного варианта, но также для отказа от всех, истории и всех заметок при каждом сохранении проекта. Локальный JSON для Codex содержит только проверяемые хэши и отзывы, а не видео.
