# Persona · приемка снятых дублей A01/B01 перед монтажом

Ветка PR #128. Новый локальный шаг **перед** Whisper/монтажом. Не заменяет существующие `tools/persona-semantic-montage.mjs` и `tools/persona-take-qa.mjs`, а вызывает их.

## Съемка: два персонажа, два отдельных исходника

- A01 — «Я актёр. И ещё пишу музыку». Крупный план, взгляд в объектив.
- B01 — «И у нас есть проблема». Средний план за клавишами.
- Снимайте вертикально (оптимально 1080p/30 fps, SDR), с запасом 1–2 с до и после реплики, 2–3 дубля на сцену. Если снято только по одному дублю, начать можно с двух файлов.
- Исходники не нужно переименовывать, резать или ретушировать. Можно указать любое имя файла с явной пометкой `A01=` или `B01=`.

## 1. Запустить приемку локально на Windows

Из корня проекта:

```powershell
npm run media:shoot:intake -- "C:\\Users\\Kostya\\Videos\\persona-intake-001" "A01=C:\\Users\\Kostya\\Videos\\IMG_0001.mp4" "B01=C:\\Users\\Kostya\\Videos\\IMG_0002.mp4"
```

Пути в примере **иллюстративные**. Вместо `npm` допустим прямой `node tools/persona-shoot-intake.mjs`, если npm недоступен. Чтобы добавить дубли, допишите `"A01=..."` и `"B01=..."` в команду. Всего: 2–12 **явно выбранных** видео, не более 6 на сцену. Каталоги не сканируются.

Каталог `persona-intake-001` **не должен существовать** до запуска: это защита от перезаписи.

Будет создано:

- `sources.json` — готовый manifest для существующего Persona-пайплайна.
- `evidence/analysis.json` — FFprobe-сведения, SHA-256 оригиналов, интервалы черных кадров, аудио-пики, яркость, признаки пауз и пр.
- `evidence/A01_take01-{1,2,3}.jpg` и аналогичные JPEG для B01 (имена вида `A01_take01-1.jpg`).
- `evidence/A01_take01-speech.wav` и аналогичные WAV для исходников с аудиодорожкой.
- `INTAKE.json` — понятный **пофайловый технический отчет**; в случае ошибки — `FAILED.json`.

**Не делается:** загрузка в Descript, облачные AI-вызовы, оценка актерской игры, изменение исходников, переписывание лица или очков, публикация.

## 2. Что проверять в INTAKE.json

- `audio_track_missing` или `cannot_transcribe_without_audio` — нет аудиодорожки; требуется исходник со звуком.
- `audio_silent_track_review` — дорожка есть, но цифровая тишина.
- `audio_very_low_peak_review` — звук очень тихий; проверить прослушиванием и, возможно, переснять.
- `audio_near_digital_ceiling` — пиковый уровень близко к 0 dBFS, возможны перегрузки; **не доказательство** клиппинга.
- `low_average_luma_review`, `high_average_luma_review` — общая яркость требует просмотра.
- `black_video_intervals` — обнаружены чёрные участки.
- `coded_orientation_review_phone_rotation_possible` — размеры закодированы горизонтально, но телефон мог сохранить rotation metadata. Проверить фактический поворот при воспроизведении.
- `short_take_review` — меньше 2 секунд, возможен обрыв фразы.

Даже отсутствие предупреждений **не означает** правильный фокус, цвет кожи, блики на очках, удачную актерскую игру или разборчивость речи. Отчет всегда `needs-human-review`. После просмотра контрольных JPEG и прослушивания клипов решить, какие дубли подходят.

## 3. Передать отобранные дубли в локальную Persona

Если приемка пройдена и речевые реплики реально произнесены:

```powershell
npm run media:first-reel:draft -- "C:\\Users\\Kostya\\Videos\\persona-intake-001\\sources.json" "docs/persona-two-line-live-asr-check-2026-10-29.json" "C:\\Users\\Kostya\\Videos\\persona-draft-001" "C:\\Users\\Kostya\\Tools\\whisper.cpp\\bin\\whisper-cli.exe" "C:\\Users\\Kostya\\Tools\\whisper.cpp\\models\\ggml-small.bin"
```

Если FFmpeg недоступен в PATH процесса, добавить шестым аргументом путь к папке FFmpeg с `ffmpeg.exe` и `ffprobe.exe`.

**Важное ограничение:** двухрепликовый бриф подходит только для первых двух сцен. Семикадровый `persona-first-reel-production-brief-2026-10-29.json` используем после съемки остальных сцен. `RESULT.json` остается в статусе `awaiting-author-review`, не публикация.
