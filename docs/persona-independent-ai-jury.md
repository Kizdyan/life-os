# Persona — независимый ИИ-совет по идеям

**Задача:** несколько ИИ действительно проверяют идеи автора, а не один ИИ притворяется разными экспертами. Это первый работающий протокол без внешних социальных метрик. Оценки — редакционные суждения, не предсказания охватов.

## С чего начать

На Windows нужны как минимум **две разные реально установленные Ollama-модели**. Проверить:

    ollama list

В \`docs/persona-jury-local-models.example.json\` указаны **НЕ настоящие имена моделей, а заменяемые placeholders**. Замени на точные локальные названия, например те, что реально показаны командой выше. Не устанавливай большие модели ради этого без отдельной оценки свободной памяти и вычислительной стоимости.

Сначала создай несколько идей:

    npm run persona:ideas -- propose "Актёрство, музыка и режиссура" "<NEW_PROPOSAL_DIR>" "docs/persona-model-servers.example.json" humor

Потом запусти независимое судейство:

    npm run persona:jury -- "<NEW_PROPOSAL_DIR>\IDEAS.json" "docs/persona-jury-local-models.example.json" "<NEW_JURY_DIR>" "docs/persona-creative-profile-v1.json"

Последний аргумент с Creative Profile необязательный, но полезный: судьи получат реальные факты из сохранённого авторского профиля (только локальным Ollama-моделям), а не выдуманную биографию. Результаты фиксируют SHA-256 версии этого профиля, но не переписывают сам профиль.

## Два реальных процесса

**Раунд 1 — независимая экспертиза.** Продюсер и драматург (опционально скептик) получают *одинаковый неизменный список* из 3–5 идей, но **не видят оценок друг друга**. Каждый — отдельный реально вызванный модельный ID. Все 3–5 идей оцениваются за один вызов каждой модели. Нужны конкретные достоинства, слабости и редакционное решение: \`advance\`, \`revise\`, \`reject\`.

**Раунд 2 — критическое обсуждение.** Каждая модель получает собственные заключения и сохранённые **чужие** вердикты, обязана обоснованно согласиться, частично согласиться или возразить, предложив правку для каждой идеи. Каждый ответ получается отдельным модельным вызовом.

По умолчанию два судьи = **четыре настоящих LLM-вызова** (по два раунда), три судьи = шесть. Вызовы выполняются последовательно, чтобы не загружать несколько больших локальных моделей в память одновременно. Роли и модели указываются в конфигурации и могут переназначаться при следующем запуске.

## Защита от имитации

- Судьи должны указывать *разные ID моделей*. Один и тот же модельный ID с разными системными промптами не считается независимыми ИИ. Совпадающие идентификаторы блокируются до запросов.
- На первой версии разрешён **только локальный loopback Ollama HTTP**. Отправка личного Creative Profile в облако и подключение внешних API не реализованы.
- Отсутствующая или плохо отвечающая модель, неправильное количество заключений, пустые доводы, дубли ID либо отсутствие второго раунда приводят к отказу. Нельзя получить успешный отчёт с фальшивыми оценками.
- Если не подключены настоящие Instagram Insights и подтверждённые внешние тренды, судьи явно получают \`instagramInsights=false\`, \`liveTrends=false\`, \`actualVideoViewed=false\`. Они **не должны** ссылаться на несуществующие источники и предсказывать «вероятность вирусности».
- Два разных имени модели не доказывают абсолютно независимую архитектуру/обучение: это лишь проверяемое различие модельных идентификаторов. Художественное решение всё равно принимает автор.

## Результаты

- \`JURY.json\` — модель, роль, источник идей и его SHA, независимые суждения первого раунда, ответы второго, расхождения, блокировки публикации.
- \`JURY.md\` — читаемый автором протокол, отсортированный по ID идеи, а не искусственно выданный за истину рейтинг просмотров.
- \`status=AWAITING_AUTHOR_IDEA_SELECTION\` — итоговая рекомендация не является выбором автора.

Открой \`JURY.md\`, выбери \`idea-1\`, \`idea-2\` и т. д. и затем используй уже созданный \`persona:ideas -- select\` для запуска ИИ-режиссёра **только по этой выбранной идее**.

Дальнейший путь: Production Brief → Local Library Asset Matcher → настоящие съёмки → Whisper → FFmpeg → B-roll review → новый MP4.

## Чего здесь пока нет

Это работающий **кодовый процесс с реальными model API запросами при настройке двух моделей**, а не доказательство, что на компьютере пользователя уже установлены два совместимых ИИ. GitHub CI использует фальшивые HTTP-ответы исключительно как тестовые заглушки и проверяет контракты, последовательность запросов и отсутствие фиктивного успеха.

Внешние тренды, истинная статистика Instagram, оценка реального актёрского исполнения по видео и независимый художественный арбитр пока не подключены. Их нельзя объявлять работающими на основании этого этапа.

Не делать merge, deployment или публикацию без разрешения автора.
