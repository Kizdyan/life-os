# Persona — визуальный контроль и безопасное кадрирование первого Reels

**Цель:** не подменять технический успех красивым кадром. Проверить исходный цвет, экспозицию, целостность лица, очков, рук и клавиш, затем вручную выбрать crop перед отдельным MP4. Никаких генеративных изменений внешности, фоновых загрузок, автопубликации или автоматического окрашивания кожи.

## Что добавлено

- `tools/persona-visual-review.mjs` — три контрольных стоп-кадра из **фактически выбранного участка** каждой сцены; средняя яркость YAVG (0–255); предупреждения о возможном пересвете, темноте и резкой смене средней яркости.
- Локальная страница `review.html`: сравни `contain` (без обрезки) и `cover` (заполнение 9:16), вручную укажи положение по X/Y.
- Браузер сохраняет `visual-framing.reviewed.json` с причиной по каждому кадру. Фото — только исходные JPEG-сэмплы; ползунки меняют **визуализацию кадрирования**, а не исходное видео.
- `tools/persona-visual-finalize.mjs` создаёт **новый** MP4 выбранного кадрирования. Пересоздаёт редактируемые субтитры, проводит FFmpeg/FFprobe QA и заново открывает художественную приёмку.
- При пересборке проверяются SHA-256 источников, совпадение кадра и его тайминга, первоначальный MP4 и техническая блокировка публикации.

**Измерения YAVG — это не оценки правильности цвета кожи, баланса белого, резкости глаз или актёрской игры.** Увеличение/уменьшение яркости и художественную цветокоррекцию автоматически не применяем, пока пользователь не выбрал реальный референс.

## Порядок после съёмки A01/B01

Сначала пройди ранее документированный цикл `media:shoot:intake` → `media:first-reel:draft` с **двухрепликовым** брифом → `media:review:kit` → ручной выбор лучших дублей → `media:review:render`.

Когда создан каталог `D:\Persona\reviewed-01` с `reviewed-timeline.json`, `reviewed-reel.mp4`, `reviewed-qa.json`, выполни в PowerShell из корня Life OS:

```powershell
$env:PATH = "C:\Users\Kostya\Tools\FFmpeg\ffmpeg-9.0.2-essentials_build\bin;$env:PATH"

npm run media:visual:review -- prepare `
  "D:\Persona\reviewed-01\reviewed-timeline.json" `
  "D:\Persona\visual-review-01"
```

`visual-review-01` должен быть **новым, не существующим каталогом**.

Создаются:

- `D:\Persona\visual-review-01\review.html` — локальная страница сравнения;
- `D:\Persona\visual-review-01\visual-review-pack.json` — источник, контрольные SHA-256, технические заметки;
- по три JPEG на каждую сцену.

Открой `review.html` обычным браузером, выбери `contain` или `cover`, вручную сдвинь кадр, посмотри лицо, очки, руки, клавиши, безопасную область для субтитров; обязательно впиши причину для каждой сцены. Нажми **«Сохранить ручное кадрирование»**. Браузер создаст `visual-framing.reviewed.json` в Downloads/«Загрузки» (путь зависит от настроек браузера).

Затем:

```powershell
npm run media:visual:finalize -- `
  "D:\Persona\reviewed-01" `
  "D:\Persona\visual-review-01\visual-review-pack.json" `
  "C:\Users\Kostya\Downloads\visual-framing.reviewed.json" `
  "D:\Persona\framed-01" `
  "C:\Users\Kostya\Tools\FFmpeg\ffmpeg-9.0.2-essentials_build\bin"
```

Каталог `framed-01` тоже должен быть новым. Если `ffmpeg` и `ffprobe` уже в PATH, последний аргумент можно опустить.

## Что получится

- `framed-reel.mp4` — новый вариант MP4 (видео 1080×1920, H.264; аудио AAC, проверяется существующим QA);
- `framed-timeline.json` — только ручные настройки crop, старый timeline неизменён;
- `captions.draft.srt` и `captions.draft.vtt` — редактируемые титры;
- `framed-qa.json` — повторная проверка звука, кадра и формата;
- `creative-review.json` — **новый пустой** чек-лист: предыдущая оценка не переносится автоматически после изменения кадра;
- `visual-decisions.json`, `VISUAL-RESULT.json` и **`VISUAL-RESULT.md`** — выбор, технические предупреждения и инструкция для просмотра.

Нужно посмотреть **весь** `framed-reel.mp4`, а не только JPG. Смена кадрирования может изменить восприятие света, пауз, расположения рук и места для титров. Ничего не публикуется автоматически.

## Как проверить технически

```powershell
node --test tools/persona-visual-review.test.mjs tools/persona-visual-finalize.test.mjs
npm run media:test
```

Новые тесты включают настоящий FFmpeg для JPEG, яркостных предупреждений, SHA-256, ручного кадрирования, новой сборки MP4, SRT/VTT и QA. **До выполнения на Windows их успех не подтверждён.** Старый показатель 95 passed / 2 skipped относится к предыдущему коммиту.

## Дальнейшая работа над цветом

После реальных A01/B01 и утверждённых референсов цвета нужно сделать безопасную редакторскую цветокоррекцию: экспозиция, баланс белого, насыщенность и согласование сцен **с обязательным сравнением до/после**. Не использовать генеративную ретушь и автоматическое исправление внешности.
