## Три направления из новой подборки

1. **Организация файлов.** Сканирование, типы, SHA-256, кандидаты на дубли, каталог, предлагаемые имена, превью плана; изменения только после утверждения. На iPhone браузер имеет доступ только к выбранным пользователем файлам, не к произвольной папке Downloads.
2. **ИИ-черновик монтажа.** Исходники + сценарий → редактируемый EDL → титры/субтитры/звук → MP4 → независимое media QA. Время «10–15 минут» в демонстрации не использовать как KPI без реального измерения.
3. **FreeLLMAPI.** Рассматривать как *исследовательского кандидата*, а не гарантированный бесплатный доступ. Слова «34 провайдера / 635 конечных точек / ~7,4 млрд токенов» относятся к заявленным суммарным квотам, не к проверенному доступному бюджету одного пользователя. Документация: https://github.com/tashfeenahmed/freellmapi . Не подменять действующую маршрутизацию; не передавать секреты в экспериментальный шлюз.

## Пользовательские и технические границы

- **Доказательство готовности:** реальный пользовательский путь на целевом устройстве + воспроизводимые тесты + проверяемый выходной файл/результат. Commit/PR/preview или синтетический тест недостаточны.
- **Безопасность:** не выполнять перенос/удаление файлов, оплату, публикации, комментарии, торговлю и подключение внешнего API без отдельного подтверждения. Пользовательские фото/видео и персональные данные не отправлять новым провайдерам при исследовании.
- **Качество Persona:** сохранять лицо, очки, пропорции и цвет кожи; проверять ориентацию, частоту кадров, аудио, уровень громкости, длительность, синхронизацию субтитров, права на музыку. Исходники неизменяемы.
- **Разработка:** не переименовывать существующие проекты/папки/чаты; не сливать PR автоматически; новые зависимости только при конкретной задаче и аудите; не разворачивать параллельную архитектуру поверх работающих модулей.
- **Область данных:** реестр содержит только функции и критерии, не личные финансовые или медицинские данные.
