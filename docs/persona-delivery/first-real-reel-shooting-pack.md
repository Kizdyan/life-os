# Актёр и композитор · пакет первой съёмки

Статус: готов к **съёмке и авторскому просмотру**, но не к публикации. Сценарий для первой репетиции — [выбранный редакторский кандидат](editorial-candidate-options.md), не утверждённый автором. Оригиналы не редактируются, публикация не включается.

## За 10 минут до записи

1. Смартфон: задняя камера, вертикально 9:16, 1080p, 30 fps, одна экспозиция и один баланс белого на все семь кадров. Заблокировать фокус на глазах; проверить, что оправа очков не ловит блик.
2. Поставить телефон на штатив. Снять A-роль чуть правее объектива, B-роль чуть левее; камеру, высоту и свет между дублями не двигать.
3. Актёр: пиджак поверх футболки, папка. Композитор: та же футболка с закатанными рукавами, у клавиш. Разница — в поведении: актёр пытается успеть и скрывает тревогу; композитор спокойно предлагает рискованное решение.
4. Записать 10 секунд тишины комнаты. Говорить на внешний микрофон или с близкого расстояния; отключить шумные приборы. В **исходном дубле** оставить по секунде живого воздуха до и после реплики: это монтажные ручки, а не часть целевого 31-секундного хронометража.

## Сразу после съёмки

1. Оставить исходники как есть и проверить каждый файл в проигрывателе. Нужны звук, фокус глаз, отсутствие бликов на очках и неотрезанные окончания слов.
2. Поместить **только выбранные для этого ролика** файлы в одну новую папку. Основной вариант: назвать семь файлов с префиксами `A01_`, `B01_`, `A02_`, `B02_`, `A03_`, `B03_`, `A04_`; можно положить несколько дублей одного кадра (`A03_take02.mp4`). Persona прочитает только эту папку, создаст `sources.json`, выполнит техническую приёмку и не изменит видео. Альтернатива — ровно два длинных файла с явными словами `actor`/`актёр` и `composer`/`композитор` в именах: техническая приёмка и ASR доступны, но границы семи сцен потребуют ручного Review, а не угадываются.
3. В PowerShell из корня Life OS выполнить. Целевую папку результата до команды не создавать:

```powershell
$env:PATH = "C:\Users\Kostya\Tools\FFmpeg\ffmpeg-9.0.2-essentials_build\bin;$env:PATH"
$selected = "D:\Persona\actor-composer-intake-01" # только эта явно выбранная папка
$brief = "docs\persona-delivery\editorial-candidate-production-brief.json"
$out = "D:\Persona\actor-composer-draft-01"

npm run media:shoot:intake -- folder `
  "$out\intake" `
  $selected

npm run media:first-reel:draft -- `
  "$out\intake\sources.json" `
  $brief `
  $out `
  "C:\Users\Kostya\Tools\whisper.cpp\bin\whisper-cli.exe" `
  "C:\Users\Kostya\Tools\whisper.cpp\models\ggml-small.bin" `
  "C:\Users\Kostya\Tools\FFmpeg\ffmpeg-9.0.2-essentials_build\bin" `
  strict
```

Для уже подготовленного списка файлов остаётся [ручной шаблон](seven-shot-sources.template.json), но он больше не нужен для обычной съёмки.

4. При полном совпадении речи команда создаст `draft-reel.mp4`, `qa.json`, `captions.draft.srt`, `captions.draft.vtt`, `decisions.json` и `RESULT.json` в `$out`. Этот MP4 предназначен только для авторского просмотра.
5. Если Whisper не нашёл реплику, это не повод подставлять текст: откройте `$out\RECOVERY-RESULT.md`, просмотрите локальную страницу кандидатов и внесите реальные границы/текст. Затем используется существующая команда `npm run media:review:render` из этого отчёта. Если аудио отсутствует — переснять дубль.

## Монтажная спецификация

- Порядок только такой: A01 → B01 → A02 → B02 → A03 → B03 → A04.
- Склейки — по завершённым мыслям; оставить реакцию A03 и начало слушания A04. Не добавлять «динамику» случайными переходами.
- Оригинальная музыка B03 начинается после последнего слова, длится около 2,1–2,5 секунды и прекращается до первой части панчлайна. Речь не нормализовать вместе с музыкальным хвостом.
- Субтитры — в черновом SRT/VTT, максимум две строки; сначала проверить текст и таймкоды, не вжигать их в изображение.
- Экспорт — H.264/AAC, 1080×1920, 30 fps. Разрешена только базовая коррекция экспозиции/баланса белого; нельзя менять внешность, очки, форму лица, тело или геометрию рук/клавиш.

## Самопроверка до авторского просмотра

| Роль | Что обязано быть верно | Что не доказывает технический QA |
|---|---|---|
| Сценарист | Два дедлайна → попытка решения → музыкальный контраст → реакция. | Оригинальность и смешное без просмотра человеком. |
| Режиссёр | Разные цели и поведение ролей, читаемые взгляды и паузы. | Убедительность мизансцены. |
| Актёр | У каждого персонажа есть действие: успеть/скрыть тревогу против успокоить/контролировать. | Органичность исполнения. |
| Монтажёр | B03 оставляет музыкальный хвост, A04 не режется, субтитр не висит на музыке. | Ритм и комедийная точность. |
| QA | H.264/AAC, 1080×1920, 30 fps, длительность, звук, чёрные кадры, неизменность источников. | Фокус глаз, кожа, очки, цвет и художественное качество. |

Публикация заблокирована до отдельного авторского просмотра и утверждения.
