# Skill Intelligence P1 — реальный статус и порядок внедрения (28.10.2026)

## Назначение
Расширение существующего AI Capacity OS, а НЕ новая автономная система.
Каталог Skills помогает находить проверяемые навыки для Persona, Erika, Life OS и DIVE M; внешний Skill не получает прав только потому, что попал в результаты поиска.

## Что добавлено
- `skill-intelligence.ts`: детерминированный поиск по локальному каталогу, определение совместимости агента/задачи, предварительный статический анализ файлов и план запуска через проверенный `routeAICapability()` и существующий `assessSkillAdmission()`.
- `skill-discovery-seeds.ts`: **ровно два исследовательских источника**, не обещание полного зеркала skills.sh:
  1. Remotion Best Practices: `https://github.com/remotion-dev/remotion/blob/main/packages/skills/skills/remotion-best-practices/SKILL.md`
  2. Find Skills: `https://github.com/vercel-labs/skills/blob/main/skills/find-skills/SKILL.md`
- `skill-intelligence.test.ts`: тесты каталогизации, статической проверки и барьеров политики.

**Важная честность статусов:** `discovery_only` означает только совпадение заявленных описаний, а `manual_install_review` — безопасный к рассмотрению план, а НЕ установленный, безопасный или доступный в рантайме Skill. `mayInstallAutomatically` и `mayExecuteAutomatically` здесь всегда `false`.

## Этапы реальной интеграции
1. **DISCOVER:** поиск по официальному каталогу https://skills.sh или ручное `npx skills find <query>`. В текущем P1 нет онлайн-синхронизации, скрытых сетевых запросов или массовой загрузки. CLI требует отдельной установки/запуска и может собирать телеметрию; при ручном использовании допускается `DISABLE_TELEMETRY=1`.
2. **INSPECT:** зафиксировать точный upstream commit SHA, полный набор исходников (не только `SKILL.md`), SHA-256, лицензию, вложенные скрипты и зависимости. Статический анализ — только сигнал о риске, а не сертификат безопасности. Неполная инвентаризация блокируется.
3. **REVIEW:** человек оценивает промпт-инъекции, лицензии, сетевые запросы, доступ к файлам, секретам и любым внешним эффектам. При наличии замечаний допуск не выдаётся.
4. **SANDBOX:** три или больше измеримых тестов на фиктивных или публичных данных; сравнение с базовым процессом без Skill по качеству, цене, задержке и стабильности. Не путать синтетические unit-тесты с реальным бенчмарком.
5. **ADMISSION:** существующий `assessSkillAdmission()` требует оценок >=0.80, полной успешности тестовых сценариев, ревью и финального разрешения. Регистрация только локальной реализации через `registerAuditedSkill()`. Текущие демо-записи не соответствуют этим требованиям.
6. **PROVIDER ROUTING:** выбрать только фактически проверенный адаптер Claude Code / Codex по измерениям и разрешениям; отсутствие такого адаптера выдаёт `no_verified_provider`.
7. **MANUAL INSTALL / QA:** после отдельного разрешения проверить что устанавливается ИМЕННО зафиксированная ревизия и файлы совпадают с digest; только потом ограниченная интеграция. P1 **не исполняет команд установки**, не меняет ~/.claude, ~/.codex, production, Supabase и секреты.
8. **OBSERVER:** подтверждённый результат, QA, rollback и лог источника; публикация, платные вызовы, удаление, credentials, отправка личных данных — только после отдельного APPROVAL.

## Запреты и ограничения
- Никакого `npx skills add --all`, `-g -y` и запуска произвольных найденных скриптов.
- Нельзя полагаться только на популярность, число звёзд или утверждение о безопасности каталога.
- Запрещены тихий доступ к приватным данным и передача исходников третьим лицам.
- Паттерн-сканер не заменяет полноценный аудит и не гарантирует отсутствие вредоносного кода.
- Не подменять с помощью Skills сами провайдеры: Skill — инструкции/инструменты; для их выполнения всё ещё нужен отдельно проверенный агент.

## Тестирование и приёмка
- Локальные unit-тесты должны подтвердить поиск, блокировку опасных пакетов и отсутствие автозапуска.
- До заявления `READY` требуется: `npm test`, `npm run typecheck`, `npm run web:build`, зелёный CI на точном SHA, реальная ревизия двух отобранных Skills и успешная изолированная задача с наблюдаемым выходом.
- На момент написания этого файла полный CI и сквозной сценарий не подтверждены, поэтому PR должен остаться Draft.
- PR P1 основан на экспериментальной ветке PR #108; не объединять автоматически с main и не дублировать медийную библиотеку PR #117.
