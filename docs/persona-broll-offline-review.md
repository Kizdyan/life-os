# Persona B-roll: визуальное утверждение архивных кадров без Codex и без облака

**Что добавлено:** локальный статический HTML-экран с реальными, проверенными FFmpeg-превью. Пользователь видит конкретные видео, выбирает или пропускает кандидата, отмечает просмотр, подтверждает права и пишет режиссёрскую причину. Браузер скачивает новый \`broll-selection.reviewed.json\` для существующего \`persona:broll render\`. Никакого локального сервера, облачных пересылок, автоматического художественного или публикационного разрешения.

Это промежуточная реализация *авторского интерфейса* между PR #140 (каталог/сопоставление кадров) и PR #141 (настоящий B-roll FFmpeg-рендер). Она не подменяет полноценное управление через приложение Persona и Local Media Worker, которое локальный Codex завершит после восстановления доступа.

## Входные материалы

Нужны четыре файла одной и той же редакции сценария:
- \`timeline.json\` — реально собранный диалоговый timeline после Whisper/FFmpeg;
- \`ASSET-MATCHES.json\` — совпадения сценария с местной библиотекой;
- \`persona-assets-v1.json\` — фактический индекс локальных видео;
- \`captions.review.json\` — субтитры исходного таймлайна.

Все четыре уже являются артефактами существующих команд. \`ASSET-MATCHES.json\` должен соответствовать версии индекса.

## 1. Создать страницу просмотра

Из корня репозитория:

    npm run persona:broll:review -- "<ORIGINAL-timeline.json>" "<ASSET-MATCHES.json>" "<persona-assets-v1.json>" "<captions.review.json>" "<NEW_REVIEW_DIR>"

В каталоге \`NEW_REVIEW_DIR\` появятся:

- \`review.html\`: офлайн-страница на русском;
- \`beat-01-candidate-01.mp4\` и другие локальные H.264 preview-клипы;
- \`selection.template.json\`: неподтверждённые предложения с SHA-подписями входных JSON;
- \`REVIEW-KIT.json\`: честный статус \`AWAITING_AUTHOR_BROLL_SELECTION\`.

Превью действительно создаются FFmpeg из имеющихся файлов только после повторной проверки их полного SHA-256 и принадлежности выбранной папке. Ни один исходный MOV/MP4 не перезаписывается. Имена файлов в HTML экранируются; скрипт работает локально, не делает внешних запросов.

## 2. Авторский просмотр

Открой \`review.html\` через проводник Windows в браузере.

Для каждой сцены предложено не более четырёх кандидатов. Можно выбрать фрагмент либо оставить «Не использовать архивный кадр». Для каждого выбранного кадра требуется:

1. Смотреть встроенное видео (сам факт просмотра человек подтверждает вручную).
2. Подтвердить наличие прав на использование выбранного материала.
3. Вписать конкретную режиссёрскую причину минимум из 10 символов.
4. Указать имя/подпись автора и отдельно отметить, что он разрешает **только локальный монтаж**, но не публикацию.

Кнопка скачивает \`broll-selection.reviewed.json\` в папку загрузок. Браузер не запускает FFmpeg: это безопасное решение без локального HTTP-сервера.

Невыбранные сцены не получают разрешения на вставку. При отсутствии выбранных вставок файл не формируется.

## 3. Создать новый настоящий MP4

    npm run persona:broll -- render "<ORIGINAL-timeline.json>" "<ASSET-MATCHES.json>" "<persona-assets-v1.json>" "<captions.review.json>" "<DOWNLOADED-broll-selection.reviewed.json>" "<NEW_RENDER_DIR>"

Команда PR #141 заново проверяет SHA входных документов и медиа, точность отрезков, источник кандидатов, явное разрешение на монтаж и права. Монтирует архивные вставки строго между полными речевыми эпизодами с заглушением только исходного звука B-roll, сдвигает последующие субтитры и запускает FFmpeg + QA. Новый MP4 и \`BROLL-RESULT.json\` остаются со статусом \`AWAITING_AUTHOR_REVIEW\` и \`publicationApproved=false\`.

## Что именно не сделано

- HTML-страница не является интегрированным разделом веб-приложения Persona; для первой версии требуется открыть файл и выбрать сохранённый JSON.
- Конкретные изображения и видео **не оценивались художественно нейросетью**; их оценивает автор.
- Первые версии B-roll — **вставки между репликами**, не overlays поверх речи. Нет автоматического саунд-дизайна для этих вставок.
- Полноценный Windows Persona UI → Media Worker E2E и проверка на реальных пользовательских дублях ещё не выполнены.
- Пробные Reels и реальные публикации Instagram — отдельная будущая интеграция с разрешённым аккаунтом.

Наличие зелёных GitHub-тестов доказывает работоспособность кода на CI и реальных FFmpeg **синтетических** исходниках, а не художественную приёмку отснятого пользователем видео.
